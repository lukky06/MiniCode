# Skill: Refactor

## When to use
Use this skill when the task asks for refactoring, simplification, restructuring, or cleanup while preserving behavior.

## Procedure
1. Identify current behavior and tests before moving code.
2. Keep changes small and reversible.
3. Prefer existing abstractions and naming conventions.
4. Run relevant tests after each meaningful change when command tools are available.
5. Explain any behavior-preserving assumptions in the final report.

## Constraints
- Do not combine refactoring with unrelated feature work.
- Do not rename public APIs unless the task explicitly asks for it.
